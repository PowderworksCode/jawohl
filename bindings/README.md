# jawohl, in other languages

Generated by [jedem][] from **jawohl's own source**. There is no hand-written
code here at all: `Stream`, `complete_json`, `Syntax` and `Validation` carry
their annotations where they are defined in `src/`, and everything in `python/`
and `node/` — manifests, module shims, build script and binding source — is
generated from them.

```sh
cargo jedem run --python test.py
cargo jedem run --node test.mjs
```

`Stream` crosses as a **handle**, so this is the real incremental parser: one
object, fed chunk by chunk, keeping its state across calls.

```python
s = jawohl.Stream.from_json_schema(schema)
for chunk in response:
    s.push(chunk)
    if s.is_irrecoverable():
        break                      # stop paying for a generation that cannot succeed
    if s.status("/query") == jawohl.Syntax.Complete:
        act_on(...)                # settled: it can no longer change
```
```js
const s = jawohl.Stream.fromJsonSchema(schema);
for (const chunk of response) {
  s.push(chunk);
  if (s.isIrrecoverable()) break;
  if (s.status("/query") === jawohl.Syntax.Complete) actOn(...);
}
```

And the one-shot completion, unchanged:

```python
jawohl.complete_json('{"query":"rust par')   # '{"query":"rust par"}'
```

Each language gets what it would have written: `snake_case` in Python and
`camelCase` in JS from the same Rust names, a static method in Python and a
factory in JS for the alternate constructor, `Option<T>` arriving as `None` and
`null`, a `Result` raising a `ValueError` and throwing an `Error`, and **states
as real enums** — a `Syntax` class in Python, a string-literal union in
TypeScript — rather than strings that only convention keeps correct.

## What is not here yet

Four `Stream` methods are marked `#[jedem(skip)]` because their return types
have no lowering yet:

| | |
|---|---|
| `snapshot`, `changes` | need **unions** — `Value` is recursive, `Event` has struct variants |
| `error`, `lowering_report` | need **records**, and return a reference |

`changes` is the one that matters: it is how you would consume events rather
than poll `status`. Polling answers the same questions today, just less
directly.

The two builders cross fine. `with_number_profile` and `with_max_depth` take
`self` and return `Self` in Rust, which names the same object, so the bindings
mutate in place and hand the same handle back — `Stream().with_max_depth(64)`
chains here exactly as it does in Rust, with no annotation on either method.

## Layout

Everything here except this file and the two host tests is generated, and every
generated file carries an `@generated` marker.

Regenerate with `JEDEM_WRITE=1 cargo test` from the repository root, or
`cargo jedem generate` here. The drift guard is part of jawohl's own test suite
— the surface is jawohl's annotations, so the check belongs with them — and it
covers every file jedem writes, not just the binding source.

A **separate workspace on purpose**: `cargo test` at the repository root should
not build pyo3 and napi.
